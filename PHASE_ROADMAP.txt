Current Status
- Phase 1: Completed

- Storage used: SQLite (better-sqlite3), not Postgres
- Backend recognition endpoints live:
  - POST /api/recognition/enroll
  - POST /api/recognition/match
  - GET /api/recognition/metrics
- Frontend is wired to backend recognition APIs and metrics panel.

Important update vs original plan
- Keep SQLite in early production/staging.
- Defer Postgres migration until scale triggers.
- Build an interface layer now so DB swap is low-risk later.

Scale triggers to move from SQLite to Postgres
- More than 50,000 recognition events per day
- More than 10 concurrent camera streams with sustained writes
- Need multi-instance backend writes
- Need advanced analytics joins/reporting at scale

SLO Targets (Instant Feel)
- Face appears to lock: less than or equal to 150 ms
- Lock to identity match: less than or equal to 120 ms
- Match to UI/socket emit: less than or equal to 80 ms
- End-to-end p95 target: less than or equal to 350 ms (stretch), less than or equal to 450 ms (acceptable early)

Recognition Stability Validation (2026-04-10)
- Live switch test executed with deterministic A->B and anti-switch oscillation sequences.
- Validation script: backend/scripts/stability-switch-test.js
- Sequence results:
  - A A A A -> confirmed A
  - wait lock -> B B B B -> identity_switched emitted and stableId moved to B
  - A A A A -> confirmed A
  - wait lock -> B A B A -> no switch (stableId remained A)
- Structured log evidence observed in live backend output:
  - identity_confirmed
  - stability_locked
  - identity_switched

New stability hardening controls (2026-04-10)
- Adaptive confirmation threshold based on pipeline latency:
  - RECOGNITION_STABILITY_ADAPTIVE_LATENCY_MS
  - RECOGNITION_STABILITY_ADAPTIVE_THRESHOLD_BOOST
- Stable confidence decay to prevent stale lock-in:
  - RECOGNITION_STABILITY_CONFIDENCE_DECAY
  - RECOGNITION_STABILITY_CONFIDENCE_MIN

Elite upgrades completed (2026-04-10)
- Multi-face per-camera stability state (top 2 tracked identities)
  - Stability engine now maintains per-camera track states and surfaces top-2 stable identities.
  - Pipeline responses now include `stableIdentities`, `pipeline.stability.activeTrackCount`, and resolved `trackId`.
  - Live validation: same-camera dual-track sequence (left/right hints) reached activeTrackCount=2 and exposed both identities simultaneously.
- Lightweight UI state contract (Detecting, Locked, Switching)
  - Backend now emits `uiState` phase contract (`detecting`, `locked`, `switching`, plus stable/lost fallbacks).
  - Camera feed UI consumes contract phase directly for status labels/colors.
  - Live validation: switch sequence emitted detecting->locked->switching->locked; anti-switch sequence emitted switching without incorrect identity flip.
